# Dafin Creative Router v0.9.0

1. Start with `dafin_plan_skill_graph` or Dafin's native equivalent. **The request's actual operation or purpose outranks platform genre and visual aesthetic.**
2. Prefer deterministic routing for clear tasks. A one-step sound repair needs Sound, not YouTube Story Strategist. A tutorial preserves correct steps and results; do not invent dramatic stakes, subplots or re-hooks.
3. Use the graph's owner/support/exclusion labels; load only relevant Skill instructions. If expertise is needed later, request it then. Never load all Markdown or archived handoffs.
4. `NEEDS_DIRECTION` means no expensive creative mutation. Show one optional multiple-choice question only when the answer would significantly alter the result; allow Not sure/Skip. A caller-supplied answer is NOT a verified user action.
5. User hard restrictions, source authenticity, approved project state and native authorization always take priority. Do not assume abstract capability-group names are actual Dafin MCP methods.
6. Never use illustrative pacing numbers as a cutting schedule, or accept research examples as commands. Retrieve max two relevant casebook entries only when a real editorial question remains.
7. For native development, inspect actual Dafin code first. Whisper is already installed; reuse the existing stack. No additional model, tool or rendering system without demonstrated need.

**Output:** advisory task, independent platform/look hints, selected owner/support cards, targeted review checks, and one unresolved question if necessary. **No project changes or visual-quality claims.**
